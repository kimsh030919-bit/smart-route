# SMART ROUTE — AI 스마트 동선 플래너

가고 싶은 장소를 담으면 **영업시간 · 정기휴무 · 임시휴무 · 브레이크 타임 · 라스트 오더 · 체류시간 ·
이동시간**을 함께 계산해, 헛걸음 없는 하루 동선과 시간대별 타임라인을 자동 생성하는 웹앱입니다.

> 해커톤 프로토타입입니다. 데모 장소/영업정보는 알고리즘 시연을 위한 **가상 데이터**이며 실제 매장
> 정보가 아닙니다. 이동시간도 실시간 교통정보가 아닌 **추정값**입니다. (앱 화면에도 동일하게 표시)

## 1. 실행 방법

```bash
cd smart-route
npm install
npm run dev          # http://localhost:5173
```

빌드 / 미리보기:

```bash
npm run build          # dist/ 생성 (base = /)
npm run preview        # 빌드 결과 확인
npm run build:relative # 하위 폴더·FTP 배포용 (base = ./)
npm run build:github   # GitHub Pages용 (base = /저장소명/)
npm run package:win    # dist → smart-route-dist.zip (Windows)
```

배포는 **[DEPLOY.md](./DEPLOY.md)** 참고 — Vercel / Netlify / Cloudflare Pages / GitHub Pages /
일반 웹호스팅 설정 파일이 모두 포함되어 있습니다. 브이월드 검색용 프록시도 플랫폼별 서버리스 함수로
들어 있습니다.

데모 시나리오 알고리즘 검증(콘솔):

```bash
npx tsx scripts/verify-demo.ts
```

### API 키 없이 바로 시연하기 (데모 모드)

키가 없으면 자동으로 **데모 모드**로 동작합니다. 헤더에 `데모 모드 (지도 API 키 없음)` 배지가 표시되고,

- 장소 검색 → 내장 데모 장소 12곳에서 검색
- 지도 → 좌표 개념도(SVG)로 번호 핀 · 경로선 · 구간별 이동시간 표시
- 최적화 / 타임라인 / 경고 / 비교 카드 → **모두 동일하게 동작**

### 브이월드(공간정보 오픈플랫폼) 연결하기

```bash
cp .env.example .env
# .env
VITE_VWORLD_API_KEY=발급받은_인증키
VWORLD_REFERER=http://localhost:5173
```

1. https://www.vworld.kr 회원가입 → **[오픈API] → [인증키 발급]**
2. 발급 신청에서 **활용 API를 반드시 체크**
   - `WMTS/TMS API` → 배경지도 타일
   - `검색 API` → 지명/주소 검색
   - `지오코더 API` → 주소 → 좌표 (출발지 설정)
3. **활용 URL(사이트 도메인)** 에 `http://localhost:5173` 등록 (등록하지 않으면 인증 실패)
4. 가입 이메일로 온 승인 메일 확인 → 키 활성화 (보통 수 분 ~ 1일)
5. `npm run dev` 재시작 → 헤더에 `브이월드 연결됨` 배지, 지도 카드에 **지도 소스: 브이월드** 선택지가 생김

**브이월드에서 받아오는 것**

| 서비스 | 엔드포인트 | 이 앱에서 쓰는 곳 |
| --- | --- | --- |
| WMTS/TMS 타일 | `https://api.vworld.kr/req/wmts/1.0.0/{key}/{layer}/{z}/{y}/{x}.png` | 배경지도 (일반/백지도/야간/위성/하이브리드 5종 전환) |
| 검색 API 2.0 | `https://api.vworld.kr/req/search?service=search&request=search&version=2.0&...` | 지명·주소로 방문 장소 검색 |
| 지오코더 2.0 | `https://api.vworld.kr/req/address?service=address&request=getcoord&version=2.0&...` | 출발지 주소 → 좌표 |
| 데이터 API | `https://api.vworld.kr/req/data?service=data&request=GetFeature&...` | (미사용. 행정경계·건물 등 필요 시 확장 지점) |

**브이월드에서 받아올 수 없는 것** — 이 서비스의 핵심 데이터입니다.

- 영업시간 / 정기휴무 / 브레이크타임 / 라스트오더 → 브이월드에 없는 정보입니다. 브이월드로 담은 장소는
  `정보 확인 필요`로 표시되고, 장소 카드에서 직접 입력하면 동선 계산에 반영됩니다.
- 길찾기 / 실시간 이동시간 → 브이월드에 없습니다. 이동시간은 계속 추정값입니다.

**CORS 주의** — 타일(이미지)은 바로 쓸 수 있지만, 검색·지오코더 **JSON API는 CORS 헤더를 주지 않습니다.**
두 가지 경로를 모두 지원합니다. (`VITE_VWORLD_TRANSPORT` 로 선택, 기본 `auto`)

| 방식 | 경로 | 비고 |
| --- | --- | --- |
| 프록시 (개발 기본) | 브라우저 → `/vworld-api/req/search` → vite dev server(Referer 주입) → `api.vworld.kr` | 배포 시엔 서버리스 함수가 같은 역할 (`api/`, `netlify/`, `functions/`) |
| JSONP (배포 기본) | 브라우저 → `api.vworld.kr/req/search?...&callback=...` | 서버가 없는 정적 호스팅(GitHub Pages 등)에서도 검색 가능 |

`auto` 는 개발에서 프록시를, 배포에서 JSONP를 쓰고, 프록시 호출이 실패하면 JSONP로 자동 폴백합니다.
서버를 둘 수 있는 환경이라면 `VITE_VWORLD_TRANSPORT=proxy` + 서버 전용 `VWORLD_API_KEY` 조합이 가장
안전합니다. (JSONP는 `api.vworld.kr` 스크립트를 페이지에서 실행하므로 그 도메인을 신뢰하게 됩니다)

### 카카오맵 연결하기

```bash
cp .env.example .env
# .env
VITE_KAKAO_MAP_KEY=발급받은_JavaScript_키
```

1. https://developers.kakao.com → 내 애플리케이션 → **앱 키 → JavaScript 키** 복사
2. 같은 앱의 **플랫폼 → Web → 사이트 도메인**에 `http://localhost:5173` 등록
3. `npm run dev` 재시작 → 헤더 배지가 `카카오맵 연결됨`으로 바뀌고, 실제 장소 검색 + 카카오맵 표시로 전환

`.env`는 `.gitignore`에 포함되어 커밋되지 않습니다. 키는 코드에 하드코딩하지 않습니다.

## 2. 화면 구성

**하루 일정 플래너 한 화면**으로 동작합니다. 상단 히어로 이미지(스크롤하면 사라짐) 아래에
출발 조건 · 장소 검색 · 방문 장소 목록이 있고, 계산하면 지도와 시간대별 일정표가 나옵니다.

### 동작 순서

1. 출발 조건 설정 (출발지 · 날짜 · 출발 시간 · 희망 종료 시간 · 이동수단)
2. 장소 검색 후 목록에 담기 (최소 2곳 ~ 최대 10곳)
   - 브이월드/카카오 검색은 영업시간을 제공하지 않으므로, 업종별 통상 운영시간으로 채운다
   - 장소 카드에서 실제 영업시간·요일별 시간·브레이크·임시휴무를 직접 입력하면 그 값이 우선
3. **최적 동선 만들기** → 시간 제약 기반 최적화(부분집합 DP)로 방문 순서 계산
4. 지도(실제 도로 경로) + 시간대별 일정표 + 경고 + 거리순 비교 표시
5. 휴무 등으로 빠진 장소에는 주변 같은 업종의 **대체 장소**를 제안하고, 교체 시 자동 재계산

## 3. 발표 시연 순서 (추천)

1. 방문 장소 목록의 **데모 장소 불러오기** 클릭
2. **최적 동선 만들기**
   - 거리순으로 가면 `데모 음식점 B`에 **14:30 도착 → 브레이크 타임(15:00~17:00)** 에 걸려 2시간 30분 대기
   - SMART ROUTE는 순서를 바꿔 **13:00 점심 시간대**에 배치 → 대기 0분
   - 하단 **단순 최단거리 순서와 비교** 카드에서 "허비되는 시간 2시간 30분 절약 · 헛걸음 1건 방지" 확인
3. 날짜를 **월요일**로 바꾸면 월요일 휴무 장소가 **일정에서 제외되고 이유와 대안 제시**
   - "출발 시간을 ○○로 바꾸면 전체 방문 가능" 같은 대안도 자동 탐색
   - 빠진 장소에는 **주변 같은 업종 대체 장소**가 제안되고, 교체하면 동선이 다시 계산됨
4. 장소 추가·삭제, 출발 시간/이동수단 변경 → **일정 다시 계산하기**
5. 체류시간/우선순위 변경, 장소 카드의 **영업시간 직접 입력**(요일별 · 임시휴무 포함) → 재계산

## 3. 구현된 기능

### 장소 입력
- 장소 이름 검색(브이월드 / 카카오맵 / 데모 데이터), 주소·좌표 표시, **출발지에서 가까운 순** 정렬
- 장소 추가·삭제, **최소 2곳 ~ 최대 10곳** 제한
- 장소별 **예상 체류시간**(숫자 입력 + 프리셋), **방문 우선순위**(꼭 가야 함/보통/여유 되면)
- 장소별 영업정보 직접 입력: 영업 시작/종료, **요일별 영업시간**, 정기 휴무일(요일 토글),
  **날짜 지정 임시 휴무**, 브레이크 타임(복수, 요일별 가능), 라스트 오더
- **방문 마감 시각** 표시: 영업 종료 − 체류시간, 라스트 오더, 브레이크 구간을 모두 고려해
  "늦어도 몇 시까지 도착해야 하는지"를 검색 결과·장소 카드·타임라인에 표시
- 검색 API는 영업시간을 제공하지 않으므로, 업종별 통상 운영시간(`src/lib/estimatedHours.ts`)으로
  채운다. 내부적으로 `source: 'estimated'` 로 기록되며 사용자가 입력하면 `user` 로 바뀐다

### 시간 제약 기반 경로 최적화 (`src/lib/optimizer.ts`)
단순 최단거리가 아니라, 부분집합 DP(Held–Karp 변형 + 파레토 상태 유지)로 시간 제약을 만족하는 순서를 찾습니다.

- 상태: `(방문한 장소 집합, 마지막 장소)` → `(일정 종료시각, 비용)` 파레토 최적 집합 (상태당 최대 4개)
- 전이: 이동시간 가산 → 도착시각 계산 → **영업 시작 전이면 대기**, **브레이크 타임과 겹치면 브레이크
  이후로 이동**, **라스트 오더 초과/영업 종료 초과면 전이 불가**
- 비용: `이동시간 + 대기시간×0.6 + 방문순서×우선순위가중치` (우선순위가 높은 곳을 앞쪽에 배치)
- 희망 종료 시간 초과 일정은 생성하지 않음
- 전체 방문이 불가능하면 **무리하게 만들지 않고** 최대한 많이 방문하는 해를 선택 + 제외 사유 설명
  (정기휴무/임시휴무/영업종료 후 도착/브레이크 충돌/체류시간 확보 불가/라스트오더 경과/종료시간 초과)
- 대안 제시: 전체 방문이 가능해지는 **출발 시간 자동 탐색**, 날짜 변경, 체류시간 축소, 우선순위 낮은 장소 분리
- `내가 정한 순서로 계산` 옵션: 최적화를 끄고 사용자가 지정한 순서를 시간 제약으로만 검증

### 결과 화면
- 요약 카드: 방문 장소 수, 일정 시간, 총 이동시간/거리, 총 체류시간, 대기시간
- 지도: 방문 순서 번호 핀, 경로선, 구간 이동시간/거리, 핀 클릭 시 상세정보(도착·이용 시간, 영업시간, 브레이크)
- 시간대별 일정표: 방문 순서, 도착 예정 시간, 예상 체류시간, 다음 장소까지 이동시간,
  영업 여부 배지, **브레이크 타임 충돌/회피 배지**, 오픈 대기, 라스트 오더 임박, 영업 종료 임박
- 경고 패널: 제외된 장소와 이유, 개선 제안, 휴무/브레이크/영업정보 알림
- **단순 최단거리 순서와 비교** 카드: 거리순 방문 시 발생하는 대기/헛걸음 vs 최적화 결과
- 일정 다시 계산하기 (장소 추가·삭제, 출발 시간/이동수단/날짜/체류시간 변경 후)
- 입력 상태는 **LocalStorage**에 저장되어 새로고침해도 유지

### 품질
- 반응형(모바일 1열 → 데스크톱 2열 + 결과 3:2 레이아웃), 네이비/블루 포인트 컬러, 둥근 카드, Pretendard
- 오류 안내: 장소 수 부족, 검색 실패, 지도 SDK 로드 실패, 계산 실패 모두 사용자 문구로 표시
- `tsc -b` 타입 체크 및 `vite build` 통과

## 4. 실제 연동이 필요한(=아직 추정/데모인) 부분

| 항목 | 현재 상태 | 실제 연동 방법 |
| --- | --- | --- |
| 지도 표시 | 브이월드 WMTS(키 있을 때) / 카카오맵 SDK(키 있을 때) / 데모 개념도 — 화면에서 전환 가능 | `VITE_VWORLD_API_KEY` 또는 `VITE_KAKAO_MAP_KEY` 설정 |
| 장소 검색 | 브이월드 검색 API(프록시 또는 JSONP) · 카카오 키워드 검색 · 데모 데이터 — 화면에서 전환 가능 | 동일 |
| 출발지 주소 검색 | 카카오 키워드 검색 → 없으면 브이월드 검색/지오코더 | 동일 |
| **영업시간·휴무·브레이크타임** | **어떤 API로도 가져오지 않음.** (브이월드·카카오 모두 제공하지 않음) 데모 데이터이거나 사용자 입력. 미확인 시 `정보 확인 필요` | 구글 Places `opening_hours`, 네이버 플레이스 등 유료·승인 필요 API 연동, 또는 자체 DB 구축 |
| **이동시간·이동거리** | **실시간 교통정보 아님.** 직선거리(Haversine) × 우회계수 ÷ 이동수단 평균속도 + 고정 오버헤드 | 카카오내비 길찾기 API, ODsay(대중교통), Google Directions 등 |
| 경로선 | 지점을 잇는 직선 | 길찾기 API의 polyline 사용 |
| 데이터 저장 | 브라우저 LocalStorage | 사용자 계정 + 서버 DB(Postgres 등) |

화면과 코드 모두에서 추정값/데모 데이터임을 명시하며, 실시간 데이터를 쓰는 것처럼 표시하지 않습니다.

### 알고리즘 핵심 예시

`영업시간 11:00~21:00 / 브레이크 15:00~17:00` 음식점에 **15:30 도착** 예정이면,

1. 15:30 시작은 첫 영업창(11:00~15:00)에 체류시간이 들어가지 않아 **불가**
2. 두 번째 창(17:00~21:00)에서 17:00 시작이 가능하면 `브레이크 타임 회피` 플래그와 함께 배치
3. 대기가 길어지거나 라스트 오더를 넘기면 그 전이를 버리고, **다른 방문 순서**를 선택
4. 어떤 순서로도 불가능하면 제외 + 사유(`브레이크 타임 충돌`) + 대안(출발 시간/체류시간 조정) 제시
